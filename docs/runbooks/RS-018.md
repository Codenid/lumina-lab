## Verificación reproducible

Ejecutar desde WSL con la cuenta autorizada y el proyecto explícito. El paso 66
comprueba recurso, revisión y runtime en Cloud Run antes de invocar la API:

```bash
gcloud run services describe luminalab-insights-api \
  --project=lumina-lab-513704 --region=us-central1 \
  --format='yaml(status.url,status.latestReadyRevisionName,status.conditions)'
gcloud run services get-iam-policy luminalab-insights-api \
  --project=lumina-lab-513704 --region=us-central1
```

Después prueba las cuatro rutas RS-018 con un token de identidad y confirma que
cada una devuelve datos:

```bash
URL="$(gcloud run services describe luminalab-insights-api \
  --project=lumina-lab-513704 --region=us-central1 --format='value(status.url)')"
TOKEN="$(gcloud auth print-identity-token)"
for path in \
  '/api/v1/insights?limit=5' \
  '/api/v1/kpis?limit=5' \
  '/api/v1/inventory-plans?limit=5' \
  '/api/v1/maintenance-risks?limit=5'; do
  curl -i -H "Authorization: Bearer $TOKEN" "$URL$path"
done
```

El script 67 registra la revisión, IAM, respuestas, conteos y logs de la
revisión. Un fallo de ruta funcional debe investigarse con la respuesta y logs
de esa ruta; `/healthz` no bloquea el grupo:

```bash
gcloud logging read \
  'resource.type="cloud_run_revision" AND resource.labels.service_name="luminalab-insights-api" AND resource.labels.revision_name="luminalab-insights-api-r8d18faca07"' \
  --project=lumina-lab-513704 --limit=100 --format=json
```
